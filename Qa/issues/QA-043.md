- Status: fixed
- Severity: minor
- Viewport: desktop 1280 and mobile 375/410
- Section / Figma node: Testimonials / 1:787 (desktop), 2:1061 (mobile)

## Expected (Figma)
No slide-indicator dots and, on mobile, no prev/next arrows under the card on desktop (1:796) or mobile (2:1061). Note: this deliberately drops the brief's active-slide indicator by user decision (user chose Figma over the brief). Follow-up user decision: the mobile arrows go too; mobile is a touch-swipe slider.

## Actual (app)
Three dots (active one is a 24x8 gradient pill) under the card on desktop (absolute, 16px below the card) and in the prev/next row on mobile.

- Figma: ../screenshots/QA-043-figma.png

## Suggested fix
Remove the Dots component; keep prev/next and accessible slide state.

## Fix
- src/components/sections/Testimonials.tsx: removed the dots. Card markup extracted into a Slide component. Below md: a horizontal scroll-snap slider (`snap-x snap-mandatory`, all slides rendered, `w-full` slides with 20px gap and `scroll-px-5`, hidden scrollbar, tabIndex 0 + aria-label for keyboard scroll, slides `role=group` / `aria-roledescription=slide` / "n of N"); no arrow buttons. A scroll handler maps scrollLeft to the slide index and updates the sr-only `role=status` "Slide n of N". md and up: unchanged prev/next arrows with wrap-around (hidden below md), no dots.
- Tests (src/components/sections/__tests__/Testimonials.test.tsx): arrows navigation and wrap-around via the status text, no dot buttons, all slides in the swipe container with labels, live text updates on scroll events.
